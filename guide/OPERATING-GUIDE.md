# Working With an LLM as a Real Collaborator

## Short version

Reliable collaboration is not `prompt → answer`. It is an operating system in which the human supplies intent, taste, authority, and correction; the agent supplies breadth, synthesis, execution, and continuity. The relationship improves only when corrections are preserved in the right layer.

## 1. Shared constitution

A compact working agreement should establish quality over agreement, direct pushback, explicit uncertainty, restrained writing, tool-grounded current facts, and verified completion. It should be small enough to remain always on.

## 2. Layering

- **Working agreement:** durable relationship posture.
- **Memory:** stable user and environment facts.
- **Skills:** procedures for recurring task classes.
- **Task context:** current goal, constraints, references, and mutable state.
- **Artifacts:** inspectable outputs and provenance.

Do not put detailed procedures in the standing prompt or temporary progress in memory.

## 3. Corrections become capability

When the agent fails, extract the class-level lesson. A one-off correction belongs in the current task. A durable preference belongs in memory. A reusable method belongs in a skill. A universal behavior belongs in the working agreement.

## 4. Operating loops

- Writing and strategy: inspect context → draft substance → critique assumptions → revise → package.
- Code and operations: inspect → act → test → read logs/output → summarize.
- Creative work: establish evidence and constraints → make → judge → iterate selectively → deliver source and final.

## 5. Autonomy budget

Autonomy should rise with reversibility and fall with external impact. Reading public information is cheap. Local reversible edits can proceed inside scope. Public posts, emails, purchases, destructive changes, and third-party integrations need explicit approval close to execution.

## 6. Failure modes

- plausible theater: claiming results that were not produced
- stale context: reviving a superseded plan
- prompt bloat: repeating every rule in every task
- memory pollution: saving temporary progress
- skill sprawl: vague overlapping procedures
- premature completion: stopping before tests or inspection
- external overreach: treating plan approval as approval to publish

## 7. Practical briefing template

```text
Goal:
Why it matters:
Deliverable:
Constraints:
Sources of truth:
Approval boundaries:
Verification required:
```

## 8. Compact constitution

Use tools when they improve correctness. Push back on weak plans. Ask only when the answer changes the work. Keep context clean. Distinguish saying, doing, and proving. Treat done as verified.
